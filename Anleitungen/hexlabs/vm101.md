## 1. Überblick

VM 101 ist der **Kubernetes Control Plane Node** deines Homelab-Clusters. Diese VM verwendet **Talos Linux**, ein immutables, API-first Betriebssystem, das speziell für Kubernetes entwickelt wurde und eine AWS EKS-ähnliche Erfahrung bietet.

### Wichtige Konzepte

- **Immutable OS**: Talos Linux ist unveränderlich und wird komplett über eine API verwaltet
- **Kein SSH**: Kein traditioneller SSH-Zugang, nur API-basierte Verwaltung über `talosctl`
- **EKS-Equivalent**: Simuliert die Managed Control Plane Erfahrung von AWS EKS
- **Single Control Plane**: Ein Control Plane Node ist für Homelab-Zwecke ausreichend

### Zweck der VM

Diese VM hostet die Kubernetes Control Plane Komponenten:

- **kube-apiserver**: REST API für alle Cluster-Operationen
- **kube-scheduler**: Pod-Scheduling auf Worker Nodes
- **kube-controller-manager**: Cluster-Zustandsverwaltung
- **etcd**: Verteilte Key-Value Datenbank für Cluster-State

## 4. VM-Erstellung in Proxmox

### Voraussetzungen

Bevor du die VM erstellst, musst du das **Talos Linux ISO-Image** herunterladen:

```bash
# Auf dem Proxmox Host (192.168.178.249) verbinden
ssh root@192.168.178.249

# In das ISO-Verzeichnis wechseln
cd /var/lib/vz/template/iso

# Talos Linux ISO herunterladen (neueste Version)
wget https://github.com/siderolabs/talos/releases/download/v1.9.2/metal-amd64.iso

# Heruntergeladene ISOs anzeigen
ls -lh /var/lib/vz/template/iso/
```

### CLI-Methode (auf Proxmox Host)

```bash
# VM erstellen
qm create 101 \
  --name k8s-master \
  --memory 8192 \
  --cores 4 \
  --cpu host \
  --net0 virtio,bridge=vmbr0 \
  --scsihw virtio-scsi-pci \
  --boot order=scsi0 \
  --ostype l26

# System-Disk erstellen (40GB auf NVMe)
qm set 101 --scsi0 local-lvm:40,format=raw

# Talos Linux ISO anhängen
qm set 101 --ide2 local:iso/metal-amd64.iso,media=cdrom

# VM starten
qm start 101
```

## 5. Talos Linux Installation

> **Wichtig**: Talos Linux funktioniert anders als traditionelle Linux-Distributionen. Die Installation erfolgt komplett über die Talos API, nicht über einen interaktiven Installer.

### 5.1 talosctl Installation (auf deinem Laptop/Workstation)

Installiere das Talos CLI-Tool auf deinem **Tuxedo InfinityBook**:

```bash
# talosctl für Linux AMD64 herunterladen
curl -sL https://talos.dev/install | sh

# Alternativ: Manuelle Installation
curl -Lo /tmp/talosctl https://github.com/siderolabs/talos/releases/download/v1.9.2/talosctl-linux-amd64
chmod +x /tmp/talosctl
sudo mv /tmp/talosctl /usr/local/bin/talosctl

# Installation verifizieren
talosctl version --client
```

**Erwartete Ausgabe:**
```
Client:
  Tag:         v1.9.2
  SHA:         ...
  Built:       ...
```

### 5.2 Talos Config-Dateien generieren

Erstelle ein Arbeitsverzeichnis und generiere die Talos-Konfiguration:

```bash
# Arbeitsverzeichnis erstellen
mkdir -p ~/homelab/talos-config
cd ~/homelab/talos-config

# Talos Config generieren
talosctl gen config homelab-cluster https://192.168.178.101:6443 \
  --output-dir .

# Generierte Dateien anzeigen
ls -la
```

**Generierte Dateien:**

- `controlplane.yaml`: Control Plane Node Konfiguration
- `worker.yaml`: Worker Node Konfiguration (wird später für VM 102 benötigt)
- `talosconfig`: Talosctl Client-Konfiguration

### 5.3 Talos Config anpassen (Optional aber empfohlen)

Bearbeite die `controlplane.yaml` für statische IP-Konfiguration:

```bash
# Öffne controlplane.yaml in deinem Editor
nano controlplane.yaml
```

Füge unter `machine.network` folgendes hinzu:

```yaml
machine:
  network:
    hostname: k8s-master
    interfaces:
      - interface: eth0
        addresses:
          - 192.168.178.101/24
        routes:
          - network: 0.0.0.0/0
            gateway: 192.168.178.1
    nameservers:
      - 1.1.1.1
      - 8.8.8.8
```

### 5.4 Talos auf VM 101 installieren

Nachdem die VM von der ISO gebootet hat, wird Talos im **Maintenance Mode** gestartet. Jetzt kannst du die Konfiguration anwenden:

```bash
# WICHTIG: VM muss von der ISO gebootet sein!
# Finde die IP, die Talos per DHCP erhalten hat
# (Schau in der Proxmox Console oder in deinem Router nach)

# Temporäre DHCP IP notieren (z.B. 192.168.178.150)
TEMP_IP="192.168.178.150"  # Ersetze mit tatsächlicher IP

# Talos Config auf die VM anwenden
talosctl apply-config --insecure \
  --nodes $TEMP_IP \
  --file controlplane.yaml

# Die VM wird sich neu booten und die statische IP verwenden
# Ab jetzt ist die VM unter 192.168.178.101 erreichbar
```

> **WICHTIG**: Nach dem Reboot wird die VM die konfigurierte statische IP (192.168.178.101) verwenden. Die Installation ist damit abgeschlossen, aber der Kubernetes Cluster ist noch nicht initialisiert!

## 6. Cluster-Initialisierung

### 6.1 talosconfig einrichten

Konfiguriere `talosctl`, um mit der VM zu kommunizieren:

```bash
# Talosconfig in Standard-Location verschieben
mkdir -p ~/.talos
cp talosconfig ~/.talos/config

# Context und Endpoints setzen
talosctl config endpoint 192.168.178.101
talosctl config node 192.168.178.101

# Verbindung testen
talosctl version
```

**Erwartete Ausgabe:**
```
Client:
  Tag:         v1.9.2
Server:
  Tag:         v1.9.2
```

### 6.2 Kubernetes Cluster bootstrappen

Jetzt initialisieren wir den Kubernetes Cluster auf dem Control Plane Node:

```bash
# Kubernetes Cluster initialisieren
talosctl bootstrap --nodes 192.168.178.101

# Dieser Befehl:
# 1. Startet etcd
# 2. Initialisiert das Cluster
# 3. Startet die Control Plane Komponenten
# 4. Generiert Zertifikate

# WICHTIG: Dieser Befehl dauert 2-5 Minuten!
```

### 6.3 Cluster-Status überwachen

Während der Bootstrap läuft, kannst du den Fortschritt überwachen:

```bash
# Service-Status anzeigen
talosctl services

# Detaillierte Logs ansehen
talosctl dmesg --follow

# Kubernetes Pod-Status (nach Bootstrap)
talosctl get members
```

**Erwartete Services nach erfolgreichem Bootstrap:**

```
SERVICE         STATE   HEALTH
etcd            Running OK
kubelet         Running OK
containerd      Running OK
apid            Running OK
trustd          Running OK
```

## 7. kubectl Konfiguration

### 7.1 kubeconfig abrufen

Talos generiert automatisch die kubeconfig. Lade sie herunter:

```bash
# kubectl installieren (falls noch nicht vorhanden)
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
chmod +x kubectl
sudo mv kubectl /usr/local/bin/kubectl

# kubeconfig von Talos abrufen
talosctl kubeconfig --nodes 192.168.178.101

# Die kubeconfig wird nach ~/.kube/config geschrieben
# und automatisch als Default-Context gesetzt
```

### 7.2 kubectl Zugriff testen

```bash

kubectl cluster-info

# Nodes anzeigen (sollte k8s-master zeigen)
```

## 10. Troubleshooting

### 10.1 VM bootet nicht von ISO

**Problem**: VM startet nicht oder zeigt Boot-Fehler

**Lösung**:

```bash
# Boot-Order überprüfen
qm config 101 | grep boot

# Sollte 'boot: order=scsi0' zeigen
# Falls nicht, korrigieren:
qm set 101 --boot order=ide2  # Temporär von CD booten
```

### 10.2 Keine Verbindung zu Talos API

**Problem**: `talosctl version` zeigt 'connection refused' oder Timeout

**Lösungsschritte**:

```bash
# 1. VM IP-Adresse überprüfen
# In Proxmox Console:
ip addr show

# 2. Netzwerk-Erreichbarkeit testen
ping 192.168.178.101

# 3. Talos API Port testen
nc -zv 192.168.178.101 50000

# 4. talosctl endpoints überprüfen
talosctl config endpoint
# Sollte 192.168.178.101 zeigen
```

### 10.3 Bootstrap hängt oder schlägt fehl

**Problem**: `talosctl bootstrap` bleibt hängen oder gibt Fehler zurück

**Diagnose**:

```bash
# Service Status prüfen
talosctl services

# Logs ansehen
talosctl logs etcd
talosctl logs kubelet

# System Logs
talosctl dmesg
```

**Häufige Ursachen**:

- Zu wenig RAM (< 8GB) → VM RAM erhöhen
- Langsame Disk I/O → Auf NVMe/SSD verschieben
- Netzwerk-Probleme → DNS und Gateway prüfen

**Lösung: Reset und neu starten**:

```bash
# Talos komplett zurücksetzen
talosctl reset --nodes 192.168.178.101 --graceful=false --reboot

# VM bootet neu in Maintenance Mode
# Warte 2-3 Minuten

# Config neu anwenden
talosctl apply-config --insecure \
  --nodes 192.168.178.101 \
  --file controlplane.yaml

# Bootstrap neu durchführen
talosctl bootstrap --nodes 192.168.178.101
```

### 10.4 kubectl kann nicht auf Cluster zugreifen

**Problem**: `kubectl get nodes` gibt Fehler

**Lösungsschritte**:

```bash
# 1. kubeconfig überprüfen
cat ~/.kube/config

# 2. Context überprüfen
kubectl config current-context

# 3. API Server Erreichbarkeit testen
curl -k https://192.168.178.101:6443/version

# 4. kubeconfig neu abrufen
talosctl kubeconfig --force --nodes 192.168.178.101
```

### 10.5 Control Plane Pods crashen

**Problem**: kube-system Pods haben Status 'CrashLoopBackOff' oder 'Error'

**Diagnose**:

```bash
# Pod Status anzeigen
kubectl get pods -n kube-system

# Detaillierte Pod-Info
kubectl describe pod <pod-name> -n kube-system

# Pod Logs ansehen
kubectl logs <pod-name> -n kube-system
```

**Häufige Fehler und Lösungen**:

- **'ImagePullBackOff'**: Netzwerk-/DNS-Problem → DNS Settings in controlplane.yaml prüfen
- **'OOMKilled'**: Nicht genug RAM → VM RAM erhöhen
- **etcd Fehler**: Korrupte Datenbank → Cluster-Reset durchführen
