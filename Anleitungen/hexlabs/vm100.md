# VM 100 - DevOps Foundation Setup Documentation

## Overview

This document provides a complete technical reference for the installation and configuration of VM 100 (devops01), which serves as the external DevOps foundation layer for the Homelab Kubernetes infrastructure. This VM resolves the "chicken-egg problem" by hosting Git repositories, container registry, and object storage outside the Kubernetes cluster.

**VM Purpose**: External dependency layer providing Gitea (Git), Harbor (Container Registry), and MinIO (S3 Storage) for the K8s cluster.

## VM Creation in Proxmox

### CLI Method (Executed on Proxmox Host)

```bash
# Connect to Proxmox host
ssh root@192.168.178.249

# Create VM
qm create 100 \
  --name devops01 \
  --memory 8192 \
  --cores 4 \
  --cpu host \
  --net0 virtio,bridge=vmbr0 \
  --scsihw virtio-scsi-pci \
  --boot order=scsi0 \
  --ostype l26

# Create system disk (40GB on SSD storage)
qm set 100 --scsi0 ssd-storage:40,format=raw

# Create data disk (300GB on SSD storage)
qm set 100 --scsi1 ssd-storage:300,format=raw

# Attach Debian 13 ISO
qm set 100 --ide2 local:iso/debian-13.2.0-amd64-netinst.iso,media=cdrom

# Start VM
qm start 100
```

## Docker Installation

### Add Docker Repository

```bash
# Create keyrings directory
sudo install -m 0755 -d /etc/apt/keyrings

# Add Docker GPG key
curl -fsSL https://download.docker.com/linux/debian/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# Set correct permissions
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Add Docker repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/debian \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Update package index
sudo apt update
```

### Relocate Docker Data Directory to /data

**Purpose**: Move Docker's data directory from system partition to dedicated data partition for better space management.

```bash
# Stop Docker service
sudo systemctl stop docker

# Create Docker daemon configuration
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<EOF
{
  "data-root": "/data/docker",
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "storage-driver": "overlay2"
}
EOF

# Create new Docker data directory
sudo mkdir -p /data/docker

# Copy existing Docker data to new location
sudo cp -a /var/lib/docker/* /data/docker/

# Start Docker with new configuration
sudo systemctl start docker
sudo systemctl enable docker

# Verify Docker Root Directory
docker info | grep "Docker Root Dir"
# Expected output: Docker Root Dir: /data/docker

# Verify disk usage
df -h /data
```

## Firewall Configuration

### Configure UFW (Uncomplicated Firewall)

```bash
# Allow SSH (CRITICAL: Must be done first to prevent lockout)
sudo ufw allow 22/tcp comment 'SSH'

# Allow service ports
sudo ufw allow 3000/tcp comment 'Gitea'
sudo ufw allow 2222/tcp comment 'Gitea SSH'
sudo ufw allow 80/tcp comment 'Harbor HTTP'
sudo ufw allow 443/tcp comment 'Harbor HTTPS'
sudo ufw allow 9000/tcp comment 'MinIO API'
sudo ufw allow 9001/tcp comment 'MinIO Console'

# Enable firewall
sudo ufw --force enable

# Verify firewall status
sudo ufw status numbered
```

**Expected UFW Status**
```
Status: active

     To                         Action      From
     --                         ------      ----
[ 1] 22/tcp                     ALLOW IN    Anywhere                   # SSH
[ 2] 2222/tcp                   ALLOW IN    Anywhere                   # Gitea SSH
[ 3] 3000/tcp                   ALLOW IN    Anywhere                   # Gitea
[ 4] 80/tcp                     ALLOW IN    Anywhere                   # Harbor HTTP
[ 5] 443/tcp                    ALLOW IN    Anywhere                   # Harbor HTTPS
[ 6] 9000/tcp                   ALLOW IN    Anywhere                   # MinIO API
[ 7] 9001/tcp                   ALLOW IN    Anywhere                   # MinIO Console
```

**Purpose**: Provides S3-compatible object storage for Kubernetes backups, artifacts, and blob storage.

```bash

  devops-network:
    external: true

  minio:
    image: minio/minio:latest
    container_name: minio

    networks:
      - devops-network
    volumes:
      - ./data:/data
    ports:
      - "9000:9000"
      - "9001:9001"

```

For administrative tasks, use the MinIO Client (mc):


## Troubleshooting

### Common Issues and Solutions

#### Issue: SSH Connection Timeout After Firewall Enable

**Symptom**: Cannot SSH to VM after enabling UFW firewall.

**Cause**: Port 22 not allowed in firewall rules before enabling UFW.

**Solution**:
```bash
# Access VM via Proxmox Console
# Login as hex

# Add SSH rule
sudo ufw allow 22/tcp comment 'SSH'

# Reload firewall
sudo ufw reload

# Verify rule
sudo ufw status
```

#### Issue: Docker Permission Denied

**Symptom**: `permission denied while trying to connect to the Docker daemon socket`

**Cause**: User not in docker group or group membership not refreshed.

**Solution**:
```bash
# Verify user is in docker group
groups hex

# If not in docker group
sudo usermod -aG docker hex

# IMPORTANT: Must disconnect and reconnect SSH session
exit
ssh hex@192.168.178.28

# Verify Docker access
docker ps
```

#### Issue: DNS Resolution Failure

**Symptom**: Cannot resolve domain names (e.g., `deb.debian.org`), apt update fails.

**Cause**: DNS servers not properly configured.

**Solution**:
```bash
# Check current DNS configuration
cat /etc/resolv.conf

# Manually set DNS servers
sudo nano /etc/resolv.conf
```

Add:
```
nameserver 1.1.1.1
nameserver 8.8.8.8
nameserver 192.168.178.1
```

```bash
# Test DNS resolution
ping -c 3 google.com
ping -c 3 deb.debian.org

# Make DNS configuration persistent
sudo nano /etc/network/interfaces
```

Ensure dns-nameservers line exists:
```
auto ens18
iface ens18 inet static
    address 192.168.178.28/24
    gateway 192.168.178.1
    dns-nameservers 1.1.1.1 8.8.8.8 192.168.178.1
```

#### Issue: Harbor Container Exit with "Address Already in Use"

**Symptom**: Harbor nginx container fails to start with port 80 conflict.

**Cause**: Another service (possibly system web server) already using port 80.

**Solution**:
```bash
# Check what's using port 80
sudo ss -tlnp | grep :80
sudo netstat -tlnp | grep :80

# If system service is running, stop it
sudo systemctl stop apache2  # or nginx if installed

# Restart Harbor
cd /data/harbor/harbor
docker compose restart
```

#### Issue: Gitea SSH Clone Fails

**Symptom**: `git clone ssh://git@192.168.178.28:2222/admin/repo.git` fails.

**Cause**: Firewall not allowing port 2222.

**Solution**:
```bash
# Add Gitea SSH port to firewall
sudo ufw allow 2222/tcp comment 'Gitea SSH'
sudo ufw reload

# Test SSH connection
ssh -p 2222 git@192.168.178.28
# Should show Gitea greeting message
```

#### Issue: MinIO Access Key Creation Not Available in UI

**Symptom**: Cannot find option to create access keys in MinIO web console.

**Cause**: MinIO Community Edition removed admin features from UI in 2025.

**Solution**: Use MinIO Client (mc) CLI tool as documented in MinIO section above.
